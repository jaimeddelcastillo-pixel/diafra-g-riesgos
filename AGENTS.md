- Document types are classified only by the SQL function clasificar_tipo_documento over each org's documento_tipos catalog (template rows have org_id NULL and are never used to classify); why: one rule for imports, Recursos and reclassification.
- Recursos (org_documentos) never references brain_* tables, and file/hash columns are immutable by trigger; why: Recursos must work without Cerebro and originals must stay intact.
- Retention of Recursos files is decided only by org_documento_retencion (DB-enforced by trigger and in purge functions); why: no path may delete a controlled or Cerebro-linked file.
- Per-plan caps (interviews, export, document extraction, pages) live only in table plan_limites, read via plan_limite/mi_plan_limite (NULL = unlimited); why: limits change by data, not code. Server-side export, when built, must enforce `exportar` from this table, not only the UI.
- La lectura de archivos (PDF/Word/imagen) vive solo en supabase/functions/_shared/documento-contenido.ts; chat-analizar-documento y brain-extract-document la comparten. Why: una sola pieza de extracción evita divergencias entre asistente y Cerebro.
- brain-extract-document recalcula SHA-256 contra org_documentos antes de leer; si no coincide se detiene con 409 y audita HUELLA_NO_COINCIDE. Why: el conocimiento nunca sale de un archivo alterado.
- Los conocimientos extraídos entran siempre por_validar con fuente tipo_fuente='archivo' (página/párrafo/sección/cita/método); si la fuente falla, el ítem se borra. Why: EXTRAER ≠ VALIDAR y sin fuente no hay trazabilidad.
- Estado de documento, copia no controlada y revisión distinta solo se guardan como propuestas desde la extracción; solo admin/RS de la empresa activa las confirman (triggers brain_documents_estado_guard / org_documentos_copia_guard). Why: la IA nunca cambia un estado oficial.
- Cada extracción deja su registro en brain_extracciones (texto enviado, salvo visión) y cada fuente guarda extraccion_id. Why: quien valida debe poder cotejar lo que la IA leyó.
- Modules are registered hybrid: DB (modulos, plan_modulos, organization_features via mi_org_tiene_modulo; estado proximamente never grants access) decides access and order; src/modules/<clave>/module.ts decides menu, routes, card and pendientes, guarded by ModuloGuard; pages shared by several modules (Recursos) live in rutasPlataforma and open with any module; why: add a module without touching menu, App routes or Inicio.
- Module headers and route ownership resolve from the module registry, including shared menu pages; support navigation uses mis_modulos commercial access and an admin presentation context without global bypass; why: keep platform navigation consistent with the supported company's access.
- Overdue review cutoff is calculated by public.folios_revision_corte for both check-folios-revision and pendientes_riesgos, preserving UTC JavaScript month overflow; why: notification and card must use one identical rule even on leap days.
- Training routes belong to their owning module registry and courses are filtered by cursos.modulo_clave; course payment rules remain independent and unchanged, because module navigation must not grant new commercial rights.
- Course access is decided only by public.mi_acceso_curso (completo / vista_previa / ninguno), enforced in RLS, exam functions/trigger and emitir-diploma, and read by screens via useCurso; Mis diplomas never filters by module (groups via mis_cursos_certificados) and lives outside module guards (also opens read-only for suspended companies, no new diplomas or DC-3); why: one rule respects course expiry and earned diplomas stay reachable.
- Tours are tracked per person in onboarding_estado (user_id, org_id NULL for plataforma, clave); each module declares its tours in module.ts `tours`, OnboardingController triggers them and never shows or writes for super_admin/support; replaying from Ayuda never deletes rows; why: tours belong to the person, not the company.
- Tour message placement uses the measured message size and available viewport space through posicionTour; why: wide targets and short screens must never push tour controls off-screen.
- Company setup checklist items are computed only by SQL public.pendientes_configuracion (per active org, filtered by contracted modules); the asistente page and the Inicio card only render it and link to existing screens; why: one source of truth for "configured", no duplicated rules in UI.
- External auditors are never org_members: everything they see goes through SECURITY DEFINER functions (auditor_mis_expedientes / auditor_ver_item / auditor_registrar_descarga_folio) and edge function auditoria-descargar, all validated by public.auditoria_validar_acceso and logged in audit_trail; why: isolation comes from non-membership, so existing RLS needs no auditor exceptions.
