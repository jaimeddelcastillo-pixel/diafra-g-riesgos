# Shared UI
- Every popup uses shared Dialog/Sheet/Drawer/AlertDialog boundaries with 90dvh, fixed header/footer, a two-axis scrollable middle and mobile margins; ModalLayout preserves native form ownership. Why: actions remain reachable without per-screen sizing.
- Every table uses the shared two-axis bounded frame with sticky headings and first column; Table provides it directly and ScrollFrames applies the same class to legacy parents without moving React nodes; document views use document-scroll-frame. Why: horizontal scrolling never requires reaching the last row.
- PasswordInput/PasswordFields owns every password field through the shared Toaster compatibility adapter, including later-mounted dialogs and legacy native inputs; preserve native handlers, values and validation, expose visibility/requirements and cryptographic generation for temporary creation, translate recognized auth errors in notifications without logging values. Why: consistent presentation without changing hosted security or individual pages.
- Password guidance never claims a generated password passed breach checks; the hosted service remains authoritative and policy settings are never weakened by UI. Why: local generation cannot establish HIBP acceptance.
- Password rules accept only a verified hosted PasswordPolicy, never legacy HTML minima; unknown policy shows pending hosted validation rather than invented rules. Confirmation is immediate and breached-password errors precede generic weak-password errors. Why: exact security presentation without claiming inaccessible settings were read.
