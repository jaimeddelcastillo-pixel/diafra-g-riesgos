- Report-template signers store optional user_id with copied name/title from active company-member profiles; manual selection clears the identity and historical templates are never linked by text matching. Autorizó eligibility is advisory via server-scoped has_role and current autorizar substitutions, never a replacement for AT issuance guards; do not implement electronic signing or rewrite historical templates; why: preserve real signer identity for future signing without changing snapshots or approval rules.

- R32 Tendencias has its own read-only audit screen at /tendencias/auditoria (menu, admin/RS only) over audit_trail tend_* rows with date/user/table/code filters, before→after, reason and origin (user vs "Sistema / migración"), and Excel export; it must not depend on the Gestión de Riesgos module. Catalog Excel import validates only file rows: existing records absent from the file never block (incomplete ones are warned, untouched) and blank formatted trailing rows are ignored; the capture pressure-objective label reads "Objetivo N Pa"; why: tenant-scoped traceability without cross-module coupling and non-blocking catalog corrections.

- R31 Catalog Excel uses a versioned header adapter and a single active-company admin/RS transactional RPC with row audit reasons and optimistic before-value checks; saturation maps to the instrument manufacturer limit, objectives preserve optional code/name/state, and missing rows and issued snapshots are untouched; the RPC is set-based (SECURITY DEFINER, one permission check, one lock per table, one upsert per sheet, bulk audit rows) and the per-row guard/audit triggers skip only for its transaction-bound catalog batch flag; why: IM-23 reversible tenant-safe catalog corrections within the 8 s statement timeout, without new columns or engine changes.

- R30 New Tendencias reports and imports share the Appendix A reference module for both standards; draft exports normalize old citations, final issuance freezes the same table server-side after snapshot creation, and historical issued/cancelled snapshots remain untouched; SQL/reference parity is tested; area suggestions stay in the protected global normative catalog and require human acceptance; why: one normative table without rewriting historical reports or calculations.

- R22 Tendencias isolates copied atdiafra calculation/report engines from tenant persistence adapters; issued Word inputs and calculation date come only from issuance snapshots, with original-source regression tests; why: preserve validated calculations and reproducible historical reports without live catalogs or embedded client identity.
- R24 Capture batch extraction uses bounded workers and isolates per-photo proposals and failures; confirmation remains sequential, shared calendar checks verify written-year priority and candidate column alignment server-side before UI date proposals, and raw exports use a guarded active-company RPC; why: recoverable human review and immutable tenant-isolated history without changing the engine.
- R25 Report detail/inbox use registry and guarded persistence; historical views are read-only, cancellation overlays snapshots, AT Excel uses xlsx-js-style; why: reproducible audited reports.
- R26 Source screen hierarchy stays separate from guarded adapters; identifiers use versioned format config, active codes a normalized tenant-unique index; why: parity without engine changes.
- R27 Tendencias normative specs live in one global reference table edited only by super_admin and are only suggested to instruments (never auto-validated); system/migration data changes set tracea.origen/motivo/autorizado_por, which audit_trigger_func records; why: human acceptance and attributed system changes (IM-20).
- R28 Changing register or system clears the pending photo and proposal; extraction runs only on an explicit user photo capture/upload (gated by fotoParaExtraer), never on a selection change; why: no wrong-sheet proposals or wasted extraction credits.
- R29 Extracted readings out of spec or >40 % from the week median are marked doubtful server-side (_shared/bitacora-lecturas marcarAtipicas), without AI; saving a week with prior readings opens a dialog listing changed cells and requiring a reason (trigger tend_semana_integridad still enforces it); instrument spec text is derived only from LIE/LSE/strictness; why: catch misreads and keep ALCOA+ corrections explicit.
